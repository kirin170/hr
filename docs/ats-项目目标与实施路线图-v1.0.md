## 1. 总目标与可验收结果

交付一套以职位和招聘需求为起点、以九阶段为骨架，覆盖社招、校招、内推，从简历入场到转正与人才复用的中文 ATS。基于现有 TalentFlow 演进，业务数据真实持久化、流程可协作可追溯、权限可控、指标可复算，并具备正式集成与上线运维条件。

总目标编号：`ats-delivery`。八个领域目标共同服务这一总目标；AWR 台账中每项工作关联一个主要领域，跨领域依赖以 `depends_on` 表达。

| 结果 | 完成判据 |
|---|---|
| 招聘业务闭环 | 职位/HC、需求、九阶段候选人、面试、Offer、入职、试用期、人才库均由真实 API 驱动；正常、拒绝、撤销和异常路径可验证。 |
| 多渠道入场 | 邮箱、单/批量上传、手工、Excel、校招门户及用户主动浏览器导入复用查重、分配、解析、确认与审计；内推仅记录推荐人/来源标识。 |
| 协作与正式集成 | 钉钉六类用途、真实邮箱及 AI 三场景在授权测试环境取得证据；外部失败可重试且可人工兜底。 |
| 可度量 | 工作台和报表受权限约束、可下钻；招聘周期在需求级计算，漏斗/渠道/三类原因/转正率有指标字典。 |
| 可控与可运维 | 服务端权限、私有附件、独立敏感授权、生命周期、访问日志及 CI/迁移/性能/备份恢复/发布回滚具备证据。 |
| 最终验收 | 必交 FR/NFR 有测试与业务验收记录；业务验收人确认主链与关键异常路径，阻断问题关闭。 |

“减少招聘周期、提升复用率、过程可归因”是业务目标。先建立周期、渠道转化、复用、处理时延等基线和统计口径，再由业务方确定改善目标；本规划不虚设改善百分比。功能完成、历史本地验证、业务验收和生产发布是不同状态。

Mock 适配器是阶段性交付及测试手段，不是正式集成完成证明。正式业务审批在钉钉 OA，本系统保留需求规定的手工兜底。

## 3. 八个领域目标与阶段门槛

### M0 工程与权限基础

目标编号：`ats-foundation`；关联任务：ATS-001、002、004～006、026。

- 真实数据持久化、候选人/职位 API 与审计链可验证，工程启动文档与实现一致。
- 身份、角色、部门范围及敏感字段权限在服务端校验；文件私有访问、生命周期与 CI 门禁具备证据。

阶段交付判据：真实数据链、受控访问、私有文件、工程门禁与可复现手册。

### M1 职位与招聘需求

目标编号：`ats-requisition`；关联任务：ATS-007。

- 职位管理与 HC 分离，OA 需求同步幂等；开始、关闭、回退和周期计算遵守 REQ-0～4。
- 周期按招聘需求计算且可追溯、可筛选，职位变动不改变已计算周期。

阶段交付判据：职位/HC、幂等需求同步、开始/关闭/回退与需求级周期可验证。

### M2 统一简历入场

目标编号：`ats-intake`；关联任务：ATS-003、008～011。

- 邮箱、上传、手工、Excel、校招门户及浏览器插件均接入统一查重、分配与时间线规则；内推仅记录推荐人/来源标识，不判定有效推荐、不自动结算。
- 解析草稿全部经人工确认后转正式，高置信度也不自动转正式；失败可降级重试，重复请求不产生重复候选人；个人意愿不被职位分配覆盖。

阶段交付判据：全部入场通道、查重/草稿/分配/监控闭环，扩展先单平台再双平台。

### M3 候选人主链与人才复用

目标编号：`ats-candidate-flow`；关联任务：ATS-012、013。

- 待分配、九阶段、归档的列表与详情使用真实 API，状态流转受条件校验并可撤销、可审计。
- 用人部门任一 PASS 按规则推进；归档入池、激活回流、万级分页与 1w+ 展示符合需求。

阶段交付判据：九阶段状态规则、可撤销动作、归档/激活及万级分页可验证。

### M4 面试协同

目标编号：`ats-interview`；关联任务：ATS-014。

- 多轮多人排期、改期、取消、登记表、代填标识、评价互看与分轮听记均可追溯。
- 日历邀请与接受占用区分明确；冲突仅提示，拒绝可改期，评价结论不自动推进候选人。

阶段交付判据：多轮排期、登记、评价、代填和听记关联可用；评价不自动转阶段。

### M5 Offer 到试用期

目标编号：`ats-offer-onboarding`；关联任务：ATS-015、016。

- Offer 六阶段及各阶段接受/不通过子状态、OA 材料、谈薪结果、背调审批与书面 Offer 发送/接受结果可跟踪，不保存薪资明细；集 A/B/C 原因独立记录和统计。
- 待入职要求书面 Offer 接受、入职时间及已发送标记齐备；确认/放弃入职、HC 回写与是否转正可验证；保温只提醒内部人事。

阶段交付判据：Offer、背调、待入职、确认/放弃和是否转正闭环。

### M6 正式集成与 AI

目标编号：`ats-integrations`；关联任务：ATS-017～022。

- 钉钉六类用途、邮箱附件获取与 AI 三场景在授权环境验证，契约、幂等、失败重试和人工兜底有证据。
- AI 采用钉钉/通义优先 + 外部模型兜底，全部结果人工确认后转正式，高置信度也不自动转正式；不作审批结论、不自动流转；第三方失败不阻断人工主流程。

阶段交付判据：钉钉六类用途、邮箱与 AI 三场景通过授权环境验证及异常回归。

### M7 经营、配置与上线

目标编号：`ats-operations`；关联任务：ATS-023～025。

- 工作台与报表使用受权限约束的真实数据，指标可下钻；招聘周期按需求级汇总且排除未关闭需求。
- 配置项、万级性能、日志审计、备份恢复、数据生命周期、发布回滚及业务验收均具备记录。

阶段交付判据：可下钻报表、完整设置、性能/安全/运维证据及业务验收齐备。

阶段是能力成熟度顺序，不要求全部串行。M0 权限/文件/CI 贯穿全过程；M6 的权限与能力验证可以在用户分配后提前进行，业务模块先走相同契约的 Mock；M7 的指标口径和测试设计应提前准备。实际任务依赖以台账为准。

### ATS-007 职位、HC、招聘需求与周期闭环

依据：FR-JOB-1～6、FR-REQ-1～9、REQ-0～4；功能需求 §4.2、PRD FR-REQ-3。前置：ATS-002、ATS-004。

- 职位 CRUD、双 Tab、MJ 编号、负责人招聘要求和虚拟职位生效；满 HC 仅提示，职位关闭不影响流程中候选人。
- Mock OA 审批通过按 oaApprovalId 幂等生成需求，开始时间必填、提报时间只读；同步信息与人事修改保存在同一需求，保留 OA 单引用及操作人/时间/前后值，重复和并发回调不重复落库。
