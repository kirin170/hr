# ATS-014 面试协同契约（实施草案）

状态：ATS-014 实施契约；日历和通知为 Mock，真实钉钉能力由后续任务验收。

## 共同规则

- 时间使用带时区的 ISO 8601 字符串，持久化为 UTC；展示和今天/明天分组按业务时区 Asia/Shanghai 计算。
- `candidateId` 和 `jobId` 是记录创建时的身份快照；同一候选人之后换职位不能让旧职位的评价进入新职位范围。服务端在创建时验证候选人与职位的对应关系，禁止客户端通过修改 ID 越权。
- 所有操作由服务端认证并执行数据范围检查；列表、导出和关联读取均使用相同权限过滤。面试官评价互看仅限本人参与的同一候选人、同一职位的面试记录，不应按候选人 ID 单独放宽权限。管理人员按授权范围访问。
- 评价的结论仅是评价数据；创建、修改或读取评价均不得改变候选人阶段。阶段操作仍走 ATS-012 既有路径。

## Interview

一条面试代表某候选人、某职位的一次轮次安排：`id`、`candidateId`、`jobId`、正整数 `round`、`mode`（`ONSITE`/`VIDEO`/`PHONE`）、`startAt`、`endAt`、`location`、`interviewerIds`（非空且去重的用户 ID 数组）、`status`、日历事件引用与创建/更新时间。一次轮次可有多名面试官；同一候选人和职位可有多轮。原数据库 `time` 与 `interviewerIds` 字符串需明确迁移映射，兼容现有授权代码的 `|id|` 精确匹配，不能将展示姓名当用户 ID。

创建前预读该候选人未撤销的部门筛选 `PASS` 记录的 `availabilitySlots`（每项 `startAt`/`endAt`）；展示来源和时间，供人工选择，不自动认定候选人已确认。筛选撤销后不再作为预读来源。结束时间必须晚于开始时间。

改期和取消分别要求非空原因，并保留操作人、时间、原值和新值的历史；取消不删除记录。日历或通知失败不得破坏主业务数据。列表以业务时区分为今天、明天及以后、昨天及以前；筛选与导出共享相同查询和授权范围，导出数据与当前筛选一致。

日历与通知通过接口注入 Mock：面试官可演示 `PENDING`、`ACCEPTED`、`DECLINED`；忙闲冲突只统计 Mock 中已接受的邀请，只提示、不阻断安排。接受表示 Mock 接受，不代表真实钉钉日程或占用。改期/取消通知全部相关方；Mock 投递结果和真实投递必须可区分。真实接入由 ATS-018 承接。

## InterviewFeedback

每条评价归属 `interviewId` 与该轮 `interviewerId`，保存结构化内容、结论、`filledById`、`filledByMode`、创建/更新时间。服务端以登录身份确定操作人：本人填写为 `SELF`；授权人代他人填写为 `PROXY`，同时记录代填人身份与时间并写操作记录；不能由客户端自行伪造操作人或代填时间。评价关联的面试官必须属于该轮面试。互看查询严格限定面试记录快照的 `candidateId` 和 `jobId`，不由客户端指定其他候选人或职位来绕过范围。

## InterviewRegistrationForm

登记表模板由字段标识、标签、类型、是否必填及选项构成，可配置和版本化；已提交的登记表保存填写时的模板快照或版本与字段值，以免后续配置变化改变历史材料。提交时按对应版本校验必填、类型和选项；记录候选人、职位、提交时间与提交来源。候选人面试前填写的入口须有明确身份和授权，不得开放可猜测的匿名读写接口；实际候选人访问方式在实施中与现有认证能力对齐。登记表与评价是不同对象。

## TranscriptLink

每个链接独立追加，至少保存 `id`、`interviewId`、候选人及职位关联、轮次、URL、添加人和时间；重复添加不能覆盖既有轮次或链接，访问受同一候选人/职位范围控制。仅保存链接不等于读取听记原文或完成 AI 评估；真实钉钉听记读取由 ATS-020 承接。需要触发评估时须走现有 AI 任务契约，不能将钉钉内置智能纪要当作评估结论。

## 验证约束

迁移和端到端验证仅使用隔离临时 MySQL 库，结束后删除该库，不能连接或修改本地 `talentflow` 库。至少覆盖多轮多人、可约时间预读、原因必填、跨职位隔离、PROXY 身份及时间、字段版本、链接追加、Mock 接受/拒绝/冲突、筛选导出一致性，以及评价前后候选人阶段不变。
