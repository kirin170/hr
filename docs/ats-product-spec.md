## 1. 产品概述与目标

### 1.1 定位

以**职位**为单元、以**阶段**为骨架的招聘流程引擎，把散落在渠道、邮箱、Excel 中的简历收敛为一条可度量、可协作的流水线。

流程主干（【官网】pipeline）：

```
职位发布 → 初筛 → 用人部门筛选 → 面试 → Offer → 入职
```

三大支柱：

1. **流程引擎**：阶段可配置、规则可自动化、动作可追踪
2. **人才数据底座**：简历解析、查重、标签、人才库沉淀与激活
3. **协作层**：HR / 用人经理 / 面试官 / 猎头 / 候选人多角色多端协同

### 1.2 目标用户与角色

| 角色 | 核心诉求 | 主要入口 |
|---|---|---|
| 招聘 HR | 批量处理简历、推进流程、协调面试、发 offer | Web 工作台（主力） |
| 用人经理 | 看推荐、给结论、确认 HC、批 offer | Web + 移动端 |
| 面试官 | 3 分钟内完成评价 | 邮件/IM 直达 + 移动端 |
| 招聘负责人 / HRD | 看漏斗、看渠道 ROI、看团队效率 | 报表中心 |
| 猎头 / RPO | 管理被授权职位、推荐候选人、查进度 | 独立登录入口【实机】 |
| 内推员工 | 分享职位、查内推进度与奖励 | 内推门户 + 移动端 |
| 校园大使 | 触达毕业生、结算奖励 | 校招模块【官网】 |
| 候选人 | 投递、查进度、自助预约面试 | 招聘门户 / 小程序【官网】 |
| 系统管理员 | 组织、角色、字段、流程、模板配置 | 设置 |

### 1.3 产品目标

- 缩短招聘周期，减少流程卡顿与人工催促
- 提升简历复用率，降低渠道与猎头成本
- 让招聘过程数据可度量、可归因
- 保证候选人体验与个人信息合规

### 1.4 非目标

- 不做完整 HRIS（考勤、薪酬核算、绩效）——这部分属 Moka People 范畴【官网】
- 不做自研测评题库，测评/背调走生态对接【官网】


### 2.3 布局原则【推导】

1. 左侧固定导航 + 顶部全局条，全局搜索可直达候选人
2. 列表页采用「筛选条 → 数据区 → 批量操作条」三段式，筛选条件常驻且可保存
3. 详情优先用右侧抽屉，保持列表上下文与滚动位置
4. 阶段 Tab 与看板同源，共享筛选条件
5. 密度可切换（紧凑/舒适），HR 日均处理数百份简历

## 3. 核心功能模块

### 3.1 工作台（总览）

**能力**

- 按招聘阶段聚合的待办卡片：筛选（待分配简历 142 / 待筛选简历 51）、录用（待发送 Offer 1 / 待入职 0）、面试（待安排 0 / 待反馈 0 / 待处理 0）【实机】
- 今日指标：今日待筛选申请 5、今日面试 0【实机】
- 重要事项按业务分类：@我 / 跟进提醒 / 猎头合同到期提醒 / 候选人评估报告 / Offer 相关 / 推荐相关 / 其他，支持「全部标记为已读」【实机】
- 页内筛选：默认招聘流程 / 全部职位；右侧入口：保温期、跟进提醒【实机】

| 项 | 说明 |
|---|---|
| 输入 | 当前用户权限范围内的候选人、面试、offer、HC 数据 |
| 输出 | 各阶段待办数量、今日任务、分类通知列表 |
| 边界 | 数字随权限与「招聘流程/职位」筛选变化；空状态需引导下一步动作 |
| 证据 | 【实机】tour-04-总览 |

**设计要点**：待办按招聘阶段聚合而非时间流，通知按业务责任分类而非消息流。

### 3.2 职位与招聘需求

**能力**

- 两个 Tab：职位 / 招聘需求（HC 审批与职位发布分离）【实机】
- 职位字段：职位编号（自动生成，如 MJ000005）、部门、招聘负责人、招聘渠道、职位来源、候选人总数、入职人数、招聘人数、面试方案【实机】
- 状态：招聘中 / 已关闭（实测 5 / 0）【实机】
- 筛选：职位编号 / 职位部门 / 渠道 / 招聘负责人 / 刷新职位或简历 / 简历更新时间【实机】
- 职位整体刷新：多渠道批量发布与刷新【官网】
- 渠道账号授权：多人协作管理发布与刷新【官网】
- HC 管理：职位与编制关联【官网】

| 项 | 说明 |
|---|---|
| 输入 | JD、部门、HC、薪资范围、招聘负责人、渠道账号、面试方案 |
| 输出 | 已发布职位、渠道发布记录、该职位候选人池与漏斗数据 |
| 边界 | ① HC 满员应提示关闭职位并对在流程候选人给出处置建议【推导】；② 面试方案为**职位级**属性，不同职位可挂不同流程【实机】；③ 职位关闭不等于候选人自动淘汰【推导】 |
| 证据 | 【实机】tour-13；【官网】pipeline |

### 3.3 候选人管理

**能力**

- 阶段 Tab 即漏斗：人才推荐 / 初筛 / 用人部门筛选 / 面试 / 沟通offer / 待入职 / 已入职 / 已归档，各带实时计数【实机】
- 左侧职位分组树（招聘中的职位 5 + 具体职位名）【实机】
- 筛选条件：公司名称、最近任职、智能匹配、渠道、来源、候选人状态（已关注 / 未锁定 / 已锁定（可操作）/ 已锁定（不可操作））、超时未处理（提醒 / 淘汰 / 退回）；支持「保存为筛选条件」「清空」【实机】
- 列表行字段：申请时间 | 职位 | 渠道 → 姓名/性别/年龄/工作年限 → 当前公司+职位 → 学校/专业/学历 → 标签（名企背景/行业专注/空白经历）→ 候选人所有者 → AI 评估（符合/不符合 + 1–5 分）→ 推荐状态【实机】
- 批量操作：用人部门分配、AI 评估结果、匹配指数、Eva 直推结果、查看状态【实机】
- 排序：默认「智能匹配」，可切换【实机】
- 顶部横幅：「有简历未进来？您有 142 份待分配简历，去看看」【实机】
- 简历解析：支持 PDF / 图片 / Word / Excel，四层解析（模块/语句/逐字/图片）【官网】
- 简历查重、自动标签、智能过滤【官网】

| 项 | 说明 |
|---|---|
| 输入 | 渠道投递、邮箱转发、批量上传、内推、Excel 导入、手工录入 |
| 输出 | 结构化候选人档案、阶段状态、标签、AI 评估分、时间线 |
| 边界 | ① 简历进入系统 ≠ 进入流程，需经「待分配」队列；② 淘汰必须选原因（进入原因分析报表）【推导】；③ 锁定态分「可操作/不可操作」两种，用于并发抢人治理【实机】；④ 去重命中需给出合并策略，合并保留全部来源与附件【推导】 |
| 证据 | 【实机】tour-11；【官网】ats、solution/ai |

### 3.4 面试管理

**能力**

- 三段分组：今天的面试 / 明天及以后的面试 / 昨天及以前的面试【实机】
- 列表列：面试信息（轮次如「初试」、形式如「现场」、时间段）、候选人、联系方式、应聘职位、面试地点、面试负责人、状态【实机】
- 工具栏：查看预约面试、导出面试安排、查看面试官日程、更多【实机】
- 筛选：职位 / 面试负责人 / 面试官 / 面试类型 / 面试地点 / 面试签到【实机】
- 面试日历、面试官组、集体面试、视频面试【官网】
- 面试提醒自动触发、多端触达【官网】
- 面试反馈：面试官评价 + 候选人评价【官网】
- 现场形态：叫号面试、扫码签到、校招选座面试【官网】
- 视频面试：免安装链接、PC+移动、音视频切换、屏幕共享、记录留存【官网】

| 项 | 说明 |
|---|---|
| 输入 | 候选人、面试轮次、面试官组、时间段、地点/会议链接、面试方案 |
| 输出 | 面试日程、日历邀请、提醒消息、结构化评价、状态（待安排/待反馈/已完成/已取消） |
| 边界 | ① 改期/取消需填原因并通知全部相关方【推导】；② 面试官提交前不可见他人评价，避免锚定【推导】；③ 日历冲突检测与自动选时段需外部日历权限【待确认】 |
| 证据 | 【实机】tour-12；【官网】pipeline、ats、videoInterview |

## 4. 功能依赖与交互关系

### 4.1 主依赖链

```
渠道/内推/猎头/导入
        ↓ 简历
   解析 → 查重 → 待分配队列
        ↓ 分配
   职位 ← HC/招聘需求审批
        ↓
  阶段流转（人才推荐→初筛→用人部门筛选→面试→沟通offer→待入职→已入职）
        ↓                    ↑
   面试方案/轮次/评价表 ──────┘
        ↓
     Offer 审批 → 接受 → 入职（eHR）
        ↓
   归档 → 人才库 → 激活 → 回流到职位
```

### 4.2 关键联动

| 联动 | 说明 | 证据 |
|---|---|---|
| 职位 → 候选人 | 候选人必须挂职位（虚拟职位例外，后分配） | 【实机】 |
| 职位 → 面试方案 | 面试流程为职位级属性，非全局唯一 | 【实机】 |
| 评价表 → 面试反馈 | 反馈字段与选项由配置决定 | 【实机】设置项 |
| 自动化规则 → 阶段流转 | 规则可替代人工推进，需可追溯 | 【官网】 |
| 权限 → 全模块可见性 | 数据范围影响所有列表与统计口径 | 【推导】 |
| 通知规则 → 业务事件 | 事件驱动，多渠道触达 | 【实机】 |
| 面试 → Offer 审批 | 审批页可查看面试评价，形成决策依据 | 【官网】 |
| Offer → 入职 → 人才库 | 入职状态回传，候选人转为入职人才库 | 【官网】 |
| 全流程数据 → 报表 | 报表口径依赖各阶段状态定义 | 【官网】 |

### 4.3 状态机（候选人）

```
主链：人才推荐 → 初筛 → 用人部门筛选 → 面试 → 沟通offer → 待入职 → 已入职
旁支：任意阶段 → 已归档（进人才库）
异常：待分配（未挂职位）/ 超时未处理（提醒→淘汰→退回）/ 锁定（可操作、不可操作）
面试子状态：待安排 / 待反馈 / 已完成 / 已取消
Offer 子状态：待发送 / 审批中 / 已发送 / 已接受 / 已拒绝
```

**约束**：状态流转必须是显式动作 + 必填校验 + 可撤销，禁止静默改状态【推导】。

## 5. 使用场景与用户流程

### 5.1 社招主流程（HR）

1. 用人经理发起 HC 申请 → 审批通过 → 创建职位（自动编号）
2. 职位多渠道发布/刷新，渠道账号统一授权
3. 简历经渠道/邮箱/内推进入 → 解析 → 查重 → 进入待分配队列
4. HR 分配职位与负责人 → 进入「人才推荐」
5. 初筛（可依 AI 评估与标签）→ 通过进入「用人部门筛选」
6. 用人经理筛选 → 通过进入「面试」
7. 安排面试（面试方案、面试官组、日历）→ 提醒 → 面试 → 面试官填评价
8. 汇总评价决策 → 进入「沟通offer」→ 发起审批（携带面试评价）
9. Offer 发放（模板、密码、有效期）→ 候选人接受
10. 自动发起入职 → 信息预收集 → 待入职 → 已入职
11. 未通过者归档进人才库，标注归档原因

### 5.2 面试官流程

收到邀请（邮件/IM）→ 确认时间 → 面试 → 3 分钟内提交结构化评价 → 不看他人评价

### 5.3 用人经理流程

看本部门职位进展与推荐候选人 → 筛选通过/淘汰 → 确认面试安排 → 批 offer → 看入职预警

### 5.4 候选人流程

招聘门户/内推/扫码投递（免登录）→ 查进度 → 自助预约面试（校招选座）→ 现场扫码签到 → 接收 offer → 提交入职资料

### 5.5 校招批量流程

建校招官网与宣讲页 → 校园大使推广 → 批量收简历 → 虚拟职位统一收口 → 批量筛选 → 批量安排/选座面试 → 叫号签到 → 校招专属人才库沉淀

### 5.6 内推流程

HR 配置内推规则与奖励 → 员工分享门户/海报 → 候选人免登录投递 → 带内推标识进入流程 → 推荐人查进度 → 达成条件后奖励结算

### 5.7 猎头流程

HR 授权职位给猎头（按标签匹配）→ 猎头登录工作台 → 自主查重后推荐 → HR 查重确认归属 → 进入流程 → 保护期内归属有效 → 质量与结算数据沉淀

### 6.3 需产品决策（我方设计取舍）

1. 目标客户是中小企业轻量版，还是中大型可配置版？决定 §3.16 的投入量级
2. 是否做候选人 C 端（门户 + 进度查询 + 自助预约）？不做则体验断裂
3. 简历解析自研、采购第三方，还是先人工兜底

5. 「招聘 → 试用期」是否作为差异化主线（注意与 Moka People 正面竞争）
6. 阶段 Tab 与看板的主次关系（实测以 Tab 为主视图）

## 7. 与现有原型的差距

现有原型 `TalentFlow`（`d:/hr/src`）已实现：工作台、简历库、招聘流程、面试安排、试用期管理、部门协同、招聘数据。

| 差距 | 说明 |
|---|---|
| 缺职位管理独立页 | 数据层已有 `Job`，无页面；需补「职位 / 招聘需求」双 Tab |
| 缺渠道与内推 | 仅有 `source` 字符串，无渠道台账、内推规则、奖励 |
| 缺 Offer 与审批 | `Approval` 类型已定义，无 Offer 阶段化与审批流 |
| 缺人才库 | 无归档、无激活、无容量与分层 |
| 缺简历监控 | 无「进入系统 / 未进入」管道可观测性 |
| 缺设置与权限 | `settings` 路由已定义但未实现；无角色、数据范围、字段权限 |
| 缺通知规则 | 仅有 `Activity` 展示，无事件→规则→渠道 |
| 缺 AI 层 | 无解析、匹配、评估、外呼 |
| 视图主次 | 原型以看板为主，实测以阶段 Tab 为主 |
| 试用期模块 | 超出 ATS 边界，但与 Moka People 的入职衔接方向一致，可保留为特色 |
