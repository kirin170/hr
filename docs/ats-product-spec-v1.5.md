## 1. 产品概述与目标

### 1.1 定位

以**职位**为单元、以**阶段**为骨架的招聘流程引擎，把散落在渠道、邮箱、Excel 中的简历收敛为一条可度量、可协作的流水线。

流程主干（【官网】pipeline）：

```
职位发布 → 初筛 → 用人部门筛选 → 面试 → 沟通offer（口头） → 待入职 → 已入职 → 试用期
```

【我方事实】v1.5 修订：① 主链在「已入职」之后增加「**试用期**」阶段，只统计候选人是否转正，不做考勤/薪酬/绩效；② 「沟通offer」与「待入职」之间还包含背调、流水材料、书面 offer 发送等环节，见 §3.0；③ 本链路为本公司实现口径，与下面【官网】的粗粒度 pipeline 不是同一粒度。

三大支柱：

1. **流程引擎**：阶段可配置、规则可自动化、动作可追踪
2. **人才数据底座**：简历解析、查重、标签、人才库沉淀与激活
3. **协作层**：HR / 用人经理 / 面试官 / 候选人多角色多端协同

### 1.2 目标用户与角色

| 角色 | 核心诉求 | 主要入口 |
|---|---|---|
| 招聘 HR | 批量处理简历、推进流程、协调面试、发 offer | Web 工作台（主力） |
| 用人经理 | 看推荐、给结论、确认 HC、批 offer | Web + 移动端 |
| 面试官 | 面试结束半小时后提交评价（可人事催促 / 代填写）【我方事实】 | 钉钉日程邀请 + 移动端 |
| 招聘负责人 / HRD | 看漏斗、看渠道 ROI、看团队效率 | 报表中心 |
| 人事经理 | 参与录用审批（钉钉 OA）【我方事实】 | 钉钉 OA |
| 人事主管 | 录用审批终审，审批后返回薪资【我方事实】 | 钉钉 OA |
| 内推员工 | 分享职位、查内推进度与奖励 | 内推门户 + 移动端 |

【我方事实】系统使用人统一来自**钉钉组织架构**，可自动识别填写人身份；上表角色中「招聘负责人」与 §3.2 职位字段的「招聘负责人」（职位级负责 HR）不是同一概念。
| 校园大使 | 触达毕业生、结算奖励 | 校招模块【官网】 |
| 候选人 | 投递、查进度、自助预约面试 | 招聘门户 / 小程序【官网】 |
| 系统管理员 | 组织、角色、字段、流程、模板配置 | 设置 |

### 1.3 产品目标

- 缩短招聘周期，减少流程卡顿与人工催促
- 提升简历复用率，降低渠道成本
- 让招聘过程数据可度量、可归因
- 保证候选人体验与个人信息合规

### 1.4 非目标

- 不做完整 HRIS（考勤、薪酬核算、绩效）——这部分属 Moka People 范畴【官网】
- 不做自研测评题库，测评走生态对接【官网】
- **背调本期不接第三方服务**：背调线下执行，系统只做材料记录与结果判定【我方事实】
- **Offer 文档、模板、密码、有效期、批量发放本期不设计**；offer 流程只做状态跟踪。**书面 offer 由 HR 线下发出，其生成与发送功能预留扩展点、本期不开发，系统只记「已发送」节点**【我方事实】
- **候选人扫 offer 二维码录入入职信息本期不设计**；招聘系统不采集、不存储入职信息【我方事实】
- **AI 能力本期为一个统一 AI 评估服务，覆盖「简历评估」与「面试听记评估」两个场景**（见 §3.0.6）；其余 AI 能力（智能外呼、Eva、AI 工坊、人才 Mapping 等）不纳入本期【我方事实】

## 3. 核心功能模块

### 3.0 主体功能实现路径【我方事实】

本节是 v1.5 的实现总纲，集中描述本公司的实际业务链路。**以下各节（§3.1–§3.19、§4、§5）中凡与本节不一致的，以本节为准。**

#### 3.0.1 简历入场：两条入场路径 + 校招独立容器

| 路线 | 来源 | 进系统时的状态 | 后续动作 |
|---|---|---|---|
| ① 投递 | 招聘网站、校招投递、内推 | 自带具体职位 | 直接进入流程「人才推荐」 |
| ② 自动抓取 | **邮箱自动获取**（接收简历邮箱，含渠道投递转发至邮箱的简历） | 未安排职位 | 进「**待分配池**」→ 人事分配职位 → 进入流程 |
| ③ 校招投递 | 校招统一入口（虚拟职位） | 带「个人意愿」字段，未定正式职位 | 进「**虚拟职位**」容器 → 人事按简历与意愿分配正式职位 → 进入流程 |

- 进入系统的方式还包括：**批量上传、单个上传、手工录入**（§3.3 输入清单保持现状，不收窄）。「业务来源」与「进入系统的方式」是两个维度，不要混写。
- **待分配池与虚拟职位两个容器并存**：前者管自动抓取/无职位简历，后者管校招简历；两者都经「人事分配职位」进入主流程。
- **分配职位只分岗位、不指定负责人**；负责人由职位自带的「招聘负责人」字段带出（§3.2）。
- 校招投递时增加「**填写个人意愿**」表单（意向岗位等），作为**简历字段**保存：只记录意愿、不驱动流程、不等于正式职位、分配后不覆盖；虚拟职位是收纳容器，二者不冲突。
- **招聘网站账号级自动抓取（爬取/授权拉取）本期不做，降级为二期评估**【我方事实，2026-11-10 暂定】：本期无职位简历的自动入场仅靠**接收简历邮箱**；招聘网站的候选人主动投递经渠道通知邮件到达邮箱的，仍属邮箱自动获取，可正常进待分配池。

#### 3.0.2 主链各阶段的实现方式（7 个阶段 + 新增试用期）

| 阶段 | 实际操作 | 系统实现要点 |
|---|---|---|
| 1 人才推荐 | 先不动 | 保持文档现状（§3.3 列表、筛选、批量操作） |
| 2 初筛 | HR 筛选；**淘汰原因选填** | 不强制填原因；归档原因报表需容忍空值并单列「未填写」 |
| 3 用人部门筛选 | **筛选人可多个**（用人经理或指定业务部门面试官）；结论 **通过 / 待定 / 淘汰** 三态；通过时附**可约面时间 + 筛选原因** | **任一 1 人通过即推进**；「待定」不设超时自动出口，人工手动调整；可约面时间需结构化并能被面试排期读取 |
| 4 面试 | 多轮、多人；提醒**只给面试官**；取消「3 分钟填评价」；**面试结束半小时提醒填评价**，或人事催促 / **代填写（需代填标识）**；存 AI 听记链接（用于生成**是否建议录用**的建议，见 §3.0.6）；**面试官可互看评价**；**日历冲突只提示**；用钉钉日历创建日程并绑定面试官时间 | 候选人侧外部提醒本期不做；代填标识由钉钉组织架构自动识别填写人身份后打标；日程创建 ≠ 时间占用，接受/拒绝由钉钉原生承担；面试官拒绝后 HR 改期重新邀约；**通过/不通过均不自动流转下一阶段** |
| 5 沟通offer | 汇总面试评估信息 → **钉钉 OA 单独走录用审批**（人事经理 → 人事主管，返回薪资）→ 人事**电话谈薪** → **口头 offer 接受/拒绝** → 背调 + 流水材料保存 → 确认 → 确定入职时间 + 发送书面 offer | **Offer 文档和模板本期不设计**（书面 offer HR 线下发、生成留口子不开发、只记「已发送」节点）；本阶段只做**状态跟踪**（当前处于哪个阶段、候选人是否接受）；拒绝需记原因做归类；审批与定薪在钉钉 OA，招聘系统不存薪资明细 |
| 6 待入职 | 已发书面 offer 进入；记录**入职时间**；**保温提醒（提醒人事跟进，内部钉钉，不触达候选人）**；两个动作：**确认入职** / **放弃入职** | 放弃入职**必填原因**做归类 → 归档；确认入职 → **自动归类到已入职**；招聘系统不采集入职信息 |
| 7 已入职 | 确认是否真的入职 | — |
| 8 试用期 | **只统计候选人是否转正** | 不做考勤/薪酬/绩效（§1.4 非目标）；§6.3-5 由待决策移入已确定 |

#### 3.0.3 全流程链路

```
招聘网站 / 校招投递 / 内推 / 邮箱 / 上传 / 手工录入
        │
        ├─ 投递（带职位）─────────────────────────────┐
        ├─ 自动抓取（无职位）→ 待分配池 → 人事分配职位 ─┤
        └─ 校招（虚拟职位 + 个人意愿）→ 人事分配职位 ───┤
                                                       ↓
   人才推荐 → 初筛 → 用人部门筛选 → 面试 → 沟通offer（钉钉OA审批 → 电话谈薪 → 口头接受）
                                                       ↓
                             背调 + 流水材料 → 背调确认
                                ├ 有问题 → 终止录用归档
                                └ 无问题 → 定入职时间 + 发书面 offer
                                                       ↓
   待入职（保温提醒）┬ 放弃入职（填原因）→ 已归档 → 人才库 → 激活回流
                     └ 确认入职 → 已入职 → 试用期（只统计是否转正）
```

#### 3.0.4 钉钉集成范围（本期确定 5 类）

| 类型 | 用途 |
|---|---|
| 消息通知 / 审批待办 | 内部协同：面试提醒、跟进提醒、工作通知卡片 |
| 组织架构与身份识别 | 系统使用人统一来自钉钉组织架构；自动识别填写人身份，用于代填标识 |
| 钉钉日历读写 | 面试日程创建、告知面试官、日程时间绑定、信息提醒、忙闲冲突提示 |
| 钉钉听记读取 | 凭读取权限取回听记转写原文 / 摘要，作为统一 AI 评估服务的素材来源（见 §3.0.6） |
| 钉钉 OA 录用审批 | 独立的录用审批流程（人事经理 → 人事主管），招聘系统不自建审批流 |

> **本期不设计**：候选人扫 offer 二维码录入入职信息（原 H2 方案撤回）。

#### 3.0.5 本期不自动流转的环节

**只有「面试决策 → offer 审批」不做自动流转，由人工跳转**；其余阶段按各自规则流转。「确认入职 → 已入职」是显式人工动作触发的自动归类，不在禁用范围内。所有状态流转仍遵守 §4.3 的「显式动作 + 必填校验 + 可撤销」。

### 3.0.6 统一 AI 评估服务【我方事实】

本期 AI 能力**不是两个独立功能，而是一个模型底座 + 两套模板**。两个场景结构相同：都是「材料 + 招聘要求 → 判断 + 依据」，因此共用同一套鉴权、脱敏、日志、AI 草稿标记、人工确认与失败降级逻辑。

| 场景 | 输入 | 输出 |
|---|---|---|
| **简历评估** | 简历文本 + **招聘要求**（岗位 JD / 用人标准） | 是否符合 / 分值 / 判断依据（沿用 §3.3 行内「AI 评估：符合/不符合 + 1–5 分」） |
| **面试听记评估** | 听记转写原文 / 摘要 + **此次面试情况** + **招聘要求** | **是否建议录用**（建议录用 / 不建议 / 待定）+ 理由 + 引用的听记依据 |

**听记侧的目标不是内容解析本身**：解析只是手段，目的是结合面试情况与招聘要求做分析评估，**得出「是否建议录用」的建议**。因此输出应为**结构化结论**（结论 + 理由 + 可点回原文的依据），而非一段描述性评语，便于筛选、统计与人工复核。

**「招聘要求」是共同输入源**【我方事实，2026-11-10 已确认】：招聘要求作为**职位级**字段，由候选人所挂职位的**「招聘负责人」导入并维护**；简历评估与面试听记评估均自动取**候选人当前所挂职位**的招聘要求，无职位（待分配池/虚拟职位）的简历不触发 AI 评估，待分配职位后再生效。

**责任边界（必须写死）**：AI 给出的只是**建议**——**不进入审批结论、不自动流转、不替代录用决策**。钉钉 OA 录用审批仍由人事经理 + 人事主管完成，审批单材料为 3 项（见 §3.5）。生成结果标注为 AI 草稿，经人工确认或编辑后方可参考；需可解释、可关闭、可人工复核，解析失败降级为人工填写；并注意匹配分偏见风险与依据缺失项（§3.12 边界）。

**模型选型【待确认】**：优先选钉钉 / 通义体系内的通用模型服务，以把候选人数据控制在企业边界内。注意**不宜直接使用钉钉 AI 听记内置的智能纪要作为评估输出**——它只能处理听记、无法用于简历评估，会让两个场景变成两套系统；听记侧只提供转写素材，评估统一由模型服务完成。钉钉 AI 听记的 27 项开放能力（含「全文摘要（AI 提炼）」「转写原文」「申请听记访问权限」）在贵司版本下是否可用、智能模板能否自定义，需开发验证。模型服务应封装为可替换的一层，后续换模型不影响主流程。

### 3.5 Offer 管理【我方事实，v1.5 重写】

**本期定性：状态跟踪，不执行发放动作。** Offer 文档、模板、企业 Logo、密码、有效期、批量设置、附件模板**本期不设计**；系统只需知悉 **① offer 当前处于哪个阶段 ② 候选人是否接受**。

**书面 offer**：由 HR 线下发出；**生成与发送功能预留扩展点、本期不开发**；系统只记录「**已发送**」这一节点及其时间，不生成文件、不发送、不存文档内容【我方事实】。

**实际链路**

1. 汇总材料并作为钉钉 OA 录用审批的依据，共 **3 项**：**候选人简历信息、面试登记表信息、录用职级**（**审批单中没有「面试评级」**，该项已从文档中移除）。「面试登记表」是面试开始前由候选人填写个人信息的表格，与「面试评价表」不是同一份。
2. **钉钉 OA 单独走录用审批**：审批人为**人事经理 + 人事主管**两级；**薪资由人事主管审批后返回**（是审批产出，不是审批输入）
3. 人事据薪资与候选人**电话谈薪**
4. 候选人**口头 offer 接受 / 拒绝**；拒绝需记录**原因**做归类分析
5. 口头接受后：**背调 + 流水材料补充**（候选人提供，可为视频/图片/PDF/Word，系统只做记录保存）→ 背调确认
   - 有问题 → **终止录用归档**
   - 无问题 → **确定入职时间 + 发送书面 offer**（HR 线下发出；生成功能留口子、本期不开发；系统只记「已发送」节点）
6. 已发送书面 offer → **进入待入职**

|---|---|
| 输入 | 面试评估汇总材料、钉钉 OA 审批结果、谈薪结果、背调与流水材料 |
| 输出 | Offer 阶段状态、是否接受、拒绝原因、入职时间、背调结论 |

## 5. 使用场景与用户流程

### 5.1 社招主流程（HR）【我方事实，v1.5 重写】

1. 用人经理发起 HC 申请 → 审批通过 → 创建职位（自动编号，职位自带「招聘负责人」）
2. 职位多渠道发布；简历经招聘网站 / 校招投递 / 内推 / 邮箱自动获取 / 批量上传 / 单个上传 / 手工录入进入系统
3. 投递带职位的简历**直接进流程**；自动抓取的无职位简历进**待分配池**，由**人事分配职位**（不指定负责人）后进入流程
4. 人才推荐 → 初筛（淘汰原因**选填**）→ 通过进入用人部门筛选
5. 用人部门筛选：多名筛选人（用人经理或指定业务部门面试官），结论 通过/待定/淘汰；**任一 1 人通过即推进**，通过时记录可约面时间与筛选原因
6. 面试：多轮多人；HR 用**钉钉日历**创建日程并邀请面试官，钉钉推送邀请，面试官接受后占用时间；冲突只提示；只提醒面试官
7. 面试结束半小时提醒填评价，或人事催促 / 代填写（带代填标识）；面试官可互看评价；存钉钉听记链接，由统一 AI 评估服务结合招聘要求给出**是否建议录用**的建议（AI 草稿 + 人工确认，不进审批、不自动流转，见 §3.0.6）
8. **人工跳转**进入沟通offer：汇总面试评估材料 → 钉钉 OA 录用审批（人事经理 → 人事主管，返回薪资）→ 电话谈薪 → 口头 offer 接受/拒绝（拒绝记原因）
9. 口头接受后：背调 + 流水材料保存 → 确认；有问题终止录用归档，无问题确定入职时间 + 发送书面 offer
10. 待入职：记录入职时间、保温提醒 → 确认入职 → 已入职 → 试用期（只统计是否转正）；或放弃入职（填原因）→ 归档
11. 未通过者归档进人才库，标注原因（选填），之后可激活回流

---

### 5.2 面试官流程

收到钉钉日程邀请 → 在钉钉内接受/拒绝/暂定 → 面试 → 面试结束半小时提醒后提交结构化评价（或人事催促/代填写，带代填标识）→ **可查看他人评价**；可贴钉钉听记链接，由 AI 结合招聘要求给出**是否建议录用**的建议草稿供确认（不进入审批结论）【我方事实】

### 5.3 用人经理流程

看本部门职位进展与推荐候选人 → 与指定业务部门面试官共同筛选（通过/待定/淘汰，任一 1 人通过即推进；通过时给可约面时间与筛选原因）→ 查看面试安排 → 看入职预警。**无权知晓薪资**；录用审批不在本角色【我方事实】

### 5.4 候选人流程

招聘门户/内推/扫码投递（校招统一入口需填写个人意愿）→ 查进度 → 自助预约面试（校招选座）→ 现场扫码签到 → **电话沟通口头 offer** → 提供背调与流水材料 → 接收书面 offer。**本期不做候选人侧面试提醒、不做扫二维码录入入职信息、不做候选人自助接收 offer**【我方事实】

### 5.5 校招批量流程

建校招官网与宣讲页 → 校园大使推广 → **虚拟职位统一投递入口收简历（投递时填写个人意愿表单）** → **人事按简历与意愿分配正式职位** → 批量筛选 → 批量安排/选座面试 → 叫号签到 → 校招专属人才库沉淀【我方事实】

### 5.6 内推流程

HR 配置内推规则与奖励 → 员工分享门户/海报 → 候选人免登录投递 → 带内推标识进入流程 → 推荐人查进度 → 达成条件后奖励结算
