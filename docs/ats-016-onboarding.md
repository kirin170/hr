# ATS-016 入职和试用期交接

- 待入职使用同一 Offer 准入函数核对当前职位、书面阶段和结果、发送时间、入职日期以及背调未标记失败。Offer 不通过仍由 Offer 动作在同一事务记录快照并归档；通用阶段接口只能使用匹配的既有失败快照。待入职放弃使用独立集 C，其他原因须填写说明。
- 人事在候选人详情执行改期、确认入职或放弃入职。改期更新 OfferRecord.onboardDate 并记录前后值；确认入职和职位 hiredCount 在同一事务内更新，撤销确认同时回退计数。并发确认依赖候选人行锁和条件更新。
- 已入职可进入试用期；结束试用期须显式记录是否转正，转正须提供日期，结果保存在 ProbationRecord。试用期页面使用真实候选人，不提供原型中的目标、绩效、评审或审批功能。旧原型数据为浏览器会话内的演示数据，不自动写入正式记录；历史正式 ProbationRecord 原样保留，不推断历史转正结论。
- 保温提醒由 worker 每分钟扫描，按入职日期的上海自然日每七天为一个周期写入内部人事站内收件箱，按候选人、招聘负责人、入职日期和周期去重；改期、离开待入职或更换负责人后旧提醒不再展示。接收者必须为该职位招聘负责人、具有 RECRUITER 角色及候选人操作权限；无符合条件的人事时不向其他人或候选人发送。七天是需求未指定频率时的实现默认值。ATS-018 在此基础上接入钉钉正式通知。
- 本次没有迁移或清理既有原型演示会话、薪资、社保或员工花名册；不增加此类采集接口。

验证：`node backend/scripts/ats016-isolated-check.mjs` 需从 backend 目录运行 `node scripts/ats016-isolated-check.mjs`，只允许本机 MySQL，创建随机隔离库并在结束时删除。该测试验证入职准入、并发计数、撤销、改期、集 C、Offer 失败快照及转正记录。测试环境同时存在其他尚未提交的迁移，不能将其结果当作独立发布验收。浏览器人工走查和真实钉钉通知仍需验证；正式钉钉通道由 ATS-018 接入。
