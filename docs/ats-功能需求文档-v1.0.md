## 1. 概述

### 1.1 定位

以**职位**为单元、以**阶段**为骨架的招聘流程系统，把散落在渠道、邮箱、Excel 中的简历收敛为一条可度量、可协作的流水线。

### 1.2 业务范围

社招 + 校招 + 内推三种招聘形态常态化运作；主链覆盖从简历入场到试用期转正的全过程。

### 1.3 产品目标

- 缩短招聘周期，减少流程卡顿与人工催促
- 提升简历复用率，沉淀人才库
- 招聘过程数据可度量、可归因
- 候选人体验与个人信息合规

### 1.4 本期明确不做（非目标）

| 不做的事 | 说明 |
|---|---|
| 考勤/薪酬/绩效 | 不做完整 HRIS；试用期只统计是否转正 |
| Offer 文档生成与发送 | 书面 offer 由 HR 线下发出，系统只记「已发送」节点；生成功能预留扩展点、本期不开发 |
| 薪资数据存储 | 薪资由人事主管在钉钉 OA 审批后返回、留在 OA 侧，系统只记「审批通过/薪资已返回」状态与谈薪结果 |
| 自建审批流 | 录用审批走钉钉 OA（人事经理 → 人事主管） |
| 第三方背调服务 | 背调线下执行，系统只做材料记录与结果判定 |
| 候选人扫 offer 二维码录入入职信息 | 不采集、不存储入职信息 |
| 候选人侧系统触达 | offer 与谈薪为电话沟通；面试环节不做候选人侧外部提醒；保温提醒只提醒人事跟进 |
| 招聘网站账号级自动抓取 | 本期自动获取仅邮箱自动获取；抓取（爬取/授权拉取）降级二期评估 |
| 其余 AI 能力 | 智能外呼、AI 问答机器人、人才 Mapping、对话式 BI 等不纳入本期 |

### 1.5 术语

| 术语 | 含义 |
|---|---|
| Pipeline | 招聘流程，候选人从进入到转正的阶段链路 |
| 待分配池 | 自动抓取的无职位简历的收纳容器，人事分配职位后进入流程 |
| 虚拟职位 | 校招统一投递入口，多部门相似岗位合并收简历，再人工分配到具体职位 |
| 个人意愿 | 校招投递时填写的意向岗位等，作为简历字段保存，不驱动流程 |
| 口头 offer | 电话谈薪后候选人口头表示接受 |
| 书面 offer | 背调确认无误、入职时间确定后由 HR 线下发出的正式文件；发出即进入「待入职」 |
| 面试登记表 | 面试开始前由候选人填写的个人信息登记表，与「面试评价表」不是同一份 |
| AI 录用建议 | AI 结合面试听记与招聘要求给出的「是否建议录用」建议，属辅助判断，不是录用决策 |
| 保温期 | offer 后至入职前的持续跟进期（提醒人事，不触达候选人） |
| 招聘要求 | 职位级字段，由职位的「招聘负责人」导入并维护，是 AI 评估的共同输入 |

## 2. 用户与角色

系统使用人**统一来自钉钉组织架构**，可自动识别填写人身份。

| 角色 | 核心职责 | 主要入口 |
|---|---|---|
| 招聘 HR | 批量处理简历、推进流程、协调面试、offer 状态跟踪 | Web 工作台 |
| 用人经理 | 参与用人部门筛选、确认 HC、查看部门进展 | Web + 移动端 |
| 面试官 | 参与筛选/面试、提交评价、互看评价 | 钉钉日程 + 移动端 |
| 职位招聘负责人 | 维护职位「招聘要求」、负责所挂职位候选人 | Web 工作台 |
| 人事经理 | 钉钉 OA 录用审批（一级） | 钉钉 OA |
| 人事主管 | 钉钉 OA 录用审批（终审，审批后返回薪资） | 钉钉 OA |
| 招聘负责人 / HRD | 看漏斗、渠道 ROI、团队效率 | 报表中心 |
| 内推员工 | 分享职位、查内推进度 | 内推门户 |
| 系统管理员 | 组织、角色、字段、流程、模板配置 | 设置 |

**薪资保密规则**：部分招聘 HR、所有用人经理、所有面试官均无权知晓薪资。

## 3. 业务总流程

### 3.1 简历入场（三条路径）

```
招聘网站投递 / 校招投递 / 内推 / 邮箱自动获取 / 批量上传 / 单个上传 / 手工录入
        │
        ├─ 投递（带职位）──────────────────────────┐
        ├─ 邮箱自动获取（无职位）→ 待分配池 → 人事分配职位 ─┤
        └─ 校招投递（虚拟职位 + 个人意愿）→ 人事分配职位 ────┤
                                                        ↓
```

| 路径 | 进系统时的状态 | 后续动作 |
|---|---|---|
| ① 投递 | 自带具体职位 | 直接进入流程「人才推荐」 |
| ② 邮箱自动获取 | 未安排职位 | 进「待分配池」→ 人事分配职位 → 进入流程 |
| ③ 校招投递 | 带「个人意愿」，未定正式职位 | 进「虚拟职位」容器 → 人事按简历与意愿分配职位 → 进入流程 |

- 进入系统的方式还包括：批量上传、单个上传、手工录入。
- **分配职位只分岗位、不指定负责人**；负责人由职位自带的「招聘负责人」字段带出。
- 个人意愿只记录、不驱动流程、分配后不覆盖。
- **简历解析**：PDF / Word / 图片附件由 AI 大模型自动解析为结构化档案草稿，HR 确认后转正式档案；解析失败降级为人工录入兜底。Excel 走单独的表格批量导入。

### 3.2 主流程（9 个阶段）

```
人才推荐 → 初筛 → 用人部门筛选 → 面试 → 沟通offer → 待入职 → 已入职 → 试用期
     （待分配池 / 虚拟职位为入场容器，不属于主链阶段）
     任意阶段可归档 → 人才库 → 激活回流
```

```
沟通offer 阶段内部链路：
汇总材料 → 钉钉OA录用审批（人事经理→人事主管，返回薪资）→ 电话谈薪
→ 口头offer接受/拒绝（拒绝记原因）→ 背调+流水材料 → 背调确认
   ├ 有问题 → 终止录用归档
   └ 无问题 → 确定入职时间 + 书面offer线下发送（系统记「已发送」）→ 待入职
```

### 3.3 各阶段规则

| 阶段 | 业务规则 |
|---|---|
| 人才推荐 | 候选人初入流程，HR 可批量筛选、打标签、AI 评估 |
| 初筛 | HR 筛选；**淘汰原因选填**（不强制），报表中空值单列「未填写」 |
| 用人部门筛选 | 筛选人可多个（用人经理或指定业务部门面试官）；结论为 **通过 / 待定 / 淘汰** 三态；**任一 1 人通过即推进**；「待定」不设超时、人工调整；通过时记录**可约面时间 + 筛选原因** |
| 面试 | 多轮、多人；提醒只给面试官；面试结束半小时提醒填评价，可人事催促/代填写（代填带标识）；面试官可互看评价；日历冲突只提示；**通过/不通过均不自动流转下一阶段** |
| 沟通offer | 见 3.2 内部链路；**面试 → offer 阶段为人工跳转**，不自动流转 |
| 待入职 | 记录入职时间（必填，可改期）；保温提醒 = 提醒人事跟进；两个出口：**确认入职**（→已入职）/ **放弃入职**（必填原因 → 归档） |
| 已入职 | 确认候选人实际入职；数据回写职位入职人数 |
| 试用期 | **只统计是否转正**，不做考勤/薪酬/绩效 |
| 已归档 | 归档原因选填；归档进人才库，可激活回流 |

### 3.4 状态流转通用约束

- 状态流转必须**显式动作 + 必填校验 + 可撤销**，禁止静默改状态
- 自动动作写入时间线，可追溯

## 4. 功能模块清单

### 4.1 工作台（总览）

- 按阶段聚合的待办卡片：待分配简历数、待筛选数、待安排面试、待评价、背调待确认、待发书面 offer、待确认入职等，点击直达对应列表
- 今日指标：今日待筛选申请、今日面试
- 重要事项通知：@我 / 跟进提醒 / 评价相关 / offer 相关等分类，支持全部已读

### 4.2 职位与招聘需求

- **职位 / 招聘需求（HC）双 Tab**，HC 审批与职位发布分离
- 职位字段：职位编号（自动生成）、部门、招聘负责人、**招聘要求（负责人导入维护）**、招聘渠道、招聘人数、入职人数、面试方案、状态（招聘中/已关闭）
- 职位筛选：编号 / 部门 / 渠道 / 招聘负责人 / 简历更新时间
- HC 满员提示关闭职位；职位关闭不自动淘汰在流程候选人

### 4.3 候选人管理

- **阶段 Tab 即漏斗**：待分配（含虚拟职位）+ 9 个主链阶段 Tab，各带实时计数；左侧职位分组树
- 筛选：公司、职位、渠道、来源、标签、锁定状态、超时未处理等，可保存筛选条件
- 列表：申请时间、职位、渠道、姓名/性别/年龄/工作年限、当前公司+职位、学校/学历、标签、AI 评估信号
- 批量操作：批量筛选结论、批量转阶段、批量标签、查看状态
- 简历查重：命中重复给出合并策略，保留全部来源与附件
- 候选人锁定：可操作 / 不可操作两种锁定态
- 候选人详情：结构化档案、时间线、阶段动作、附件

### 4.4 面试管理

- 列表三段分组：今天 / 明天及以后 / 昨天及以前
- 字段：轮次、形式、时间段、候选人、职位、地点、面试负责人、状态（待安排/待反馈/已完成/已取消）
- **钉钉日历排期**：系统创建日程邀请面试官 → 钉钉推送 → 面试官接受后占用时间（创建 ≠ 占用）；拒绝后 HR 改期重新邀约；忙闲冲突只提示不自动避让
- 面试评价：结构化评价表；结束半小时自动提醒；人事可催促/代填（带代填人标识并记入操作记录）
- 面试登记表：面试前候选人填写，作为 OA 录用审批材料之一
- AI 听记评估：面试记录可贴钉钉听记链接（按轮次存，不覆盖），系统取回转写素材后由 AI 结合面试情况与招聘要求给出「是否建议录用」的建议草稿
- 改期/取消需填原因并通知相关方

### 4.5 Offer 管理（状态跟踪）

**本期定性：只跟踪状态，不执行发放动作。**

- OA 审批材料 **3 项**：候选人简历信息、面试登记表信息、录用职级（**无「面试评级」**；AI 建议不进审批单）
- 钉钉 OA 录用审批：人事经理 → 人事主管；薪资由人事主管审批后返回（留在 OA 侧）
- 电话谈薪 → 口头 offer 接受/拒绝（拒绝必记原因）
- 背调与流水材料：候选人提供（视频/图片/PDF/Word），系统只做记录保存；背调确认有问题 → 终止录用归档
- 书面 offer：HR 线下发出，系统只记「已发送」节点及时间
- 已发送书面 offer → 进入待入职
- 状态由**人事手工回填**为主

**Offer 阶段状态**（名称可再定）：待汇总材料 → OA 审批中 → 薪资已返回·待谈薪 → 电话谈薪中 → 口头已接受/已拒绝（记原因）→ 背调与流水补充中 → 背调确认 → 待发书面 offer → 已发送 → 待入职

### 4.6 待入职 / 已入职 / 试用期

| 阶段 | 规则 |
|---|---|
| 待入职 | 进入条件：入职时间已确定 且 书面 offer 已发送；入职时间必填可改期；保温提醒（只提醒人事）；出口：确认入职 / 放弃入职（必填原因） |
| 已入职 | 显式「确认入职」动作触发自动归类；回写职位入职人数 |
| 试用期 | 只统计是否转正（是/否 + 转正时间） |

不采集入职信息、不建花名册/薪资/社保档案。

### 4.7 人才库

- 已归档/淘汰候选人自动沉淀，可检索、打标签
- 归档原因分析（选填原因含「未填写」档）
- **激活闭环**：从人才库捞回候选人 → 重新挂职位进入流程
- 容量：列表单次展示上限 10000 人，超出靠筛选收窄

### 4.8 内推

- 内推门户：职位实时同步、员工分享、候选人免登录投递
- 内推简历带标识，HR 可优先处理
- 推荐人可查内推进度
- 奖励结算规则（何时算有效推荐）**待确认**，本期先做推荐与进度记录，奖励结算仅记录不自动计算

### 4.9 校园招聘

- **虚拟职位**作为校招统一投递入口；投递时填写**个人意愿**表单（意向岗位等）
- 人事按简历 + 意愿**人工分配**正式职位（本期不做自动分配）
- 校招专属人才库沉淀
- 批量筛选、批量安排面试等批量能力按通用候选人管理实现

### 4.10 消息通知

| 规则 | 说明 |
|---|---|
| 触达渠道 | 内部角色统一走**钉钉**（工作通知/卡片/审批待办） |
| 面试提醒 | 只提醒面试官 |
| 评价提醒 | 面试结束半小时自动提醒；人事可催促 |
| 保温提醒 | 提醒人事跟进，不触达候选人 |
| 超时提醒 | 长时间未处理简历提醒 |
| 候选人侧 | 本期不做任何系统触达（offer/谈薪为电话） |

### 4.11 报表

固定报表为主：

- 招聘漏斗（各阶段数量与转化率）
- 渠道质量分析
- 招聘周期与效率
- **三类原因独立归类分析**：淘汰/归档原因（含「未填写」）、offer 拒绝原因、放弃入职原因
- 试用期转正率
- 职位 360（进展、HC 详情）

所有指标可下钻到明细；指标口径在页面标注。

### 4.12 AI 能力（本期范围）

**一个统一 AI 评估服务（一个模型底座 + 三套模板）**：

| 场景 | 输入 | 输出 |
|---|---|---|
| 简历解析 | PDF/Word/图片附件 | 结构化档案草稿（HR 确认后转正式） |
| 简历评估 | 简历文本 + 职位招聘要求 | 符合/不符合 + 1–5 分 + 判断依据 |
| 面试听记评估 | 听记转写 + 面试情况 + 职位招聘要求 | 建议录用/不建议/待定 + 理由 + 可回原文的依据 |

**责任边界（对三个场景统一适用）**：

- AI 产出均为**草稿**，标注 AI 生成，人工确认或编辑后方可参考
- **不进入审批结论、不自动流转、不替代录用决策**
- 可解释（输出判断依据）、可关闭、可人工复核
- 解析/评估失败降级为人工处理
- 候选人无职位或职位未维护招聘要求时，AI 评估不可用并提示补录

### 4.13 权限

- 权限模型：**功能权限 × 数据范围 × 字段级** 三维
- 薪资相关：系统不存薪资明细；部分招聘 HR、所有用人经理、所有面试官无权知晓薪资
- 背调材料、银行流水属敏感个人信息：独立访问权限 + 保留期限
- 字段级权限需细化到用户/用户组

## 6. 部署与运行约束

| 项 | 约束 |
|---|---|
| 部署形态 | **单租户**（一套服务一个企业），数据模型无租户维度 |
| 云环境 | 阿里云 |
| 候选人入口 | 招聘门户公网域名 + HTTPS |
| 钉钉回调 | 需公网可达的回调地址 |
| 附件存储 | 对象存储 + 私有读 + 临时签名 URL，支持视频/图片/PDF/Word 多格式；设生命周期删除策略 |
| 数据保留 | 候选人数据访问日志留存，满足审计要求 |
