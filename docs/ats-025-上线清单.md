## 4. 发布与回滚步骤（待演练）

> 下列步骤为文档，**本轮未在测试环境执行**，演练证据缺失，属 B8。

### 4.1 发布

1. 确认 `dev` 已合入 `master`（PR + quality/secret-scan 两项检查通过 + 至少 1 人评审）。
2. 备份生产数据库并记录备份标识与时间点。
3. 部署 API/Worker/Web 制品；`APP_ENV`、`LOCAL_AUTH_ENABLED` 必须为生产取值，**不得带 `admin/admin` 本机账号**。
4. 执行 `npm run db:migrate:deploy`，随后 `db:migrate:status` 确认 up to date。
5. 冒烟：健康检查、登录、候选人列表、简历入场、面试排期、报表各一次。
6. 观察脱敏日志与告警 15 分钟。

### 4.2 回滚

1. 保留上一版制品与上一份数据库备份标识。
2. 应用回滚：切回上一版制品。
3. **迁移回滚需逐条评估**：本仓库迁移为前向脚本，未提供 down 脚本；涉及删列/改约束的迁移必须先从备份恢复，不得直接反向执行。
4. 回滚后重跑冒烟并记录结论。

### 4.3 测试环境必须验证的项

- HTTPS 与域名白名单：钉钉回调地址与开发者后台登记值完全一致；`localhost` 与 `127.0.0.1` 不混用。
- 脱敏日志：日志、审计与错误信息中不出现联系方式、附件内容、令牌与密钥。
- 告警：数据库/Redis 不可用、队列积压、集成连续失败能触发。
- 备份恢复：从备份恢复到独立库并校验关键表计数与约束。
- 数据生命周期：`retention:purge` 在测试库跑一次，确认同时删除对象文件与结构化记录、解绑入场记录并写审计；**保留期限具体值仍待业务确认**。
